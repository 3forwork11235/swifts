# «Стрижи» — устройство игры

3D-бои боевых дронов на Three.js: кампания, схватки и командные бои против ботов и с друзьями.
Тот же стек, что у «Лучника», «Ножей» и «Фей»: плоские скрипты без сборщика, комната работает в браузере
создателя игры, связь P2P → запасной MQTT → server.py, PWA и Android-обёртка.

## 1. Главная идея: три слоя

```
 ┌────────────── общее ядро (одинаково у комнаты и у игрока; тестируется в Node) ──────────────┐
 │ core.js  data.js  world.js  flight.js  predict.js                                           │
 └──────────────────────────────────────────────────────────────────────────────────────────────┘
 ┌────────────── «сервер» (в браузере создателя; в Node — тесты) ───────┐   ┌──── клиент ─────────┐
 │ ai.js  sim.js  combat.js  sites.js  modes.js  missions.js  room.js   │   │ meta models fx      │
 │ Arena (бой) ← директор режима ← SwiftHub (места, лобби, раунды)      │   │ render view hud     │
 └──────────────────────────────────────────────────────────────────────┘   │ input audio net     │
                                                                             │ client app          │
                                                                             └─────────────────────┘
```

* **Ядро** не знает ни о странице, ни о сети. Всё, что должно совпадать у хоста и клиента (мир, физика полёта,
  числа баланса, сверка предсказания), лежит здесь и покрыто тестами `tools/test_*.js` (запуск: `node tools/test_all.js`).
* **«Сервер»** — это `SwiftHub` (`room.js`) с `Arena` внутри. Он живёт в браузере создателя игры (в одиночной игре — в
  том же окне). Гости подключаются к нему как к настоящему серверу. Поэтому одиночная игра идёт тем же кодом,
  что и сетевая: клиент не отличает «у меня всё локально» от «играем по сети».
* **Клиент** только показывает и вводит. Правила боя клиент не считает (кроме собственного полёта — см. §4).

## 2. Мир (`world.js`)

* Карта = `(id, seed)`. Здания — набор прямоугольных коробок (AABB), сложенных в сетку 64 м. Хост и все клиенты
  строят мир сами из зерна (`mulberry32`), по сети идёт только зерно и контрольная сумма (`world.hash`).
* Запросы: `hitSphere` (столкновение дрона), `rayHit` (луч: пули, ракеты, обзор ИИ, камера), `los`, `freePoint`,
  `route` (кольца маршрута — между кольцами проверяется свободный путь), `pickSites` (расстановка зениток).
* Три генератора: `genCity` (кварталы, ярусные башни, мосты, шпиль в центре), `genCanyon` (мезы, арки, стена по краю),
  `genPort` (причалы, контейнеры, краны, суда, платформа, маяк).
* Рендер (`render.js`) склеивает все коробки в один меш с текстурой окон/страт и отдельный меш неона.

## 3. Бой (`sim.js`, `combat.js`, `sites.js`, `ai.js`, `modes.js`)

`Arena` — вся симуляция, не знает о сети. Шаг 30 Гц (`SW.TICK`), в каждом шаге:
директор режима → ввод (человек или ИИ) → полёт (`Flight.step`) → оружие → пули/ракеты/ловушки → зенитки → контакты →
бонусы. Оружие: мини-пушка (снаряды, нагрев), лазер (мгновенный луч, энергия), ракета «Шершень» (захват в конусе,
самонаведение с упреждением, потеря цели вне конуса обзора, ловушки отвлекают), зенитные ракеты, зенитки-«Ёрш».
Помощь прицела — на стороне комнаты (притягивает луч/пули к цели в конусе, у лазера без упреждения).

Идентификаторы: игроки/боты — 1…8 (0 означает «никого»), враги СТРАЖа — от 100, зенитки — 1000+номер.
Команды: в «Схватке» у каждого своя (`team = id`), в «Командах» — 0/1, в «Рейсе» игроки 0, враги 1.

Директоры режимов (`modes.js`): `Ffa`, `Team`, `Run`. `Run` читает сценарий из `missions.js`
(кольца, уничтожение зениток, волны, босс «Матка», ядро с пилонами, бесконечный режим), считает жизни команды,
реплики по радио, звёзды и награду.

ИИ (`ai.js`) выдаёт тот же ввод, что и человек (`d.in`), поэтому у ботов те же ограничения полёта.
Решения: цель → угроза-ракета (ловушки и «бочка») → точка полёта → обход зданий лучами → рули и огонь.
Сложность (`SW.DIFF`): реакция, разброс, упреждение, шанс уклониться, частота ракет.

## 4. Сеть и предсказание

* Протокол (`room.js`): `create_game / join_game / resume / in / start_game / restart / to_lobby / set_opts / loadout /
  team / emote / pause / ping / leave` ← клиент; `joined / lobby / slots / round / snap / me / roster / round_end /
  resumed / pong / error / game_closed` → клиент. Версия протокола `SW.PROTO` проверяется при входе.
* **Снимок** (`snap`, 15 Гц): все дроны (положение ×10 в целых, курс/тангаж ×1000, флаги), ракеты, состояние зениток,
  состояние режима, события боя. Пушечные трассеры чужих дронов клиент рисует сам по флагу «стреляет» (событиями не шлём).
* **`me`** — личное сообщение: точное состояние своего дрона (`st`), `ack` (номер последней принятой команды) и все
  показатели (энергия, ракеты, захват…).
* **Предсказание** (`predict.js`): свой дрон двигается сразу той же `Flight.step`, каждый шаг пронумерован и уходит в
  комнату. По `me` сверяем состояние на шаге `ack` с записанным: малая ошибка — мягкое подтягивание (с правкой записи
  будущих шагов), большая (удар, возрождение) — установка состояния комнаты и повтор наших команд после `ack`.
  Тест при задержке 0–180 мс: `tools/test_predict.js`.
* **Чужие дроны** — интерполяция между двумя снимками «из прошлого» (задержка подстраивается под джиттер),
  события боя разыгрываются, когда до их времени доходит это «прошлое».
* **Связь** (`net.js`): перенесена из «Фей» без изменения логики: гость сначала пробует WebRTC (PeerJS + TURN),
  через 6 с параллельно — MQTT через публичные серверы; третий путь — `server.py` по Wi-Fi.
  Потерявшийся игрок возвращается по токену; пока его нет, дроном управляет бот.

## 5. Клиент

* `render.js` — сцена, небо, мир, реестр визуалов (дроны, ракеты, зенитки, кольца, бонусы), автоподбор разрешения.
* `models.js` — процедурные модели (4 корпуса игрока, 5 дронов СТРАЖа, ракеты, зенитки, пилоны, ядро); статичные части
  склеиваются в один меш на материал. `fx.js` — частицы, трассеры (InstancedMesh), лучи лазера, ударные кольца.
* `view.js` — камера (за дроном с защитой от стен, из кабины, наблюдение, после гибели), фон меню и сцена ангара.
* `hud.js` — прицел с шкалами нагрева/энергии, рамки целей, захват, упреждение, тревога ракет, радар, цели задания.
* `input.js` — клавиатура, мышь-стик, сенсорный джойстик и кнопки, геймпад; счётчики нажатий не теряются при потере пакета.
* `audio.js` — весь звук синтезируется (WebAudio): оружие, взрывы, двигатель, тревога, музыка.
* `meta.js` — профиль и настройки (localStorage): ангар, достижения, задания дня, прохождение кампании.

## 6. Как добавить своё

* **Карту**: функция-генератор в `world.js` + строка в `SW.MAPS` (`data.js`) + палитра в `THEMES` (`render.js`).
* **Миссию**: объект в `SW.MISSIONS` (`missions.js`): `obj.type` — `rings | destroy | waves | boss | core | endless`.
* **Корпус / оружие / врага**: числа в `data.js`; модель — функция в `models.js`.
* **Режим**: класс-директор в `modes.js` с методами `init/update/onKill/onSiteKill/spawn/canRespawn/respawnDelay/state/info/summary`.

```
tools/viewer.html            просмотр моделей, мира и эффектов
```
